## Подтверждения последующих прогонов, 12.10.2026

- **CI #38282947269**, коммит `88654b3d017e6fed7a4c9ef5b5e7e0c6196f27cd`, https://github.com/Mika-dot/Cad/actions/runs/38282947269 — Windows/Linux **PASS**, 29/29 исходных тестов ядра, две оптимизационные итерации в `--self-test`, отдельный запуск 3 итераций. Созданы реальные BMP и CSV как два выгружаемых GitHub Actions артефакта. Третий шаг: `p=(1.017,0.744) mm`, `V=20928.68 mm³`, `m=0.164290 kg`, `VMmax=6.031 MPa`, `Umax=0.002515 mm`, `compliance=2.486468 Nmm`, `Rx=-1000 N`, `relative equilibrium residual=1.45e-9`. Три последовательных шага уменьшили регуляризованный FEM объём с `25043.84` до `20928.68 mm³` (≈16.43%).
- **CI #38283184813**, коммит `ed49b13f3e13d4bd2456d8d99c852a8c060f8177`, https://github.com/Mika-dot/Cad/actions/runs/38283184813 — **PASS** независимая матрица `Ke(24×24)` из исходного `FEM_Voxel/openscad_gen/fem.py` против C# при полностью заполненном 10×10×10 Hex8: относительная ошибка Фробениуса `3.919232911526e-16`; симметрия C# `8.104225816401e-18`. Исходный Python FEM backend отдельно решил бар 100×10×10 мм с `ν=0`: `U=0.005000000 mm`, `Rx=-1000.0000000 N`, относительная невязка `2.392e-14`. Это настоящая межъязыковая проверка формул и решения стержня, **не** сопоставление результатов shape-vs-SIMP.
- **CI #38283250741**, коммит `702ff87469b42d5faf062f8d43f0a618a997ca6c`, https://github.com/Mika-dot/Cad/actions/runs/38283250741 — **PASS** зависимость погрешности FVM от пространственного разрешения пяти М-образов при *неизменной* фоновой FEM: аналитическое F даёт `22643.931 mm³`; 8×6×6 M даёт `25043.839` (абсолютная ошибка `2399.908 mm³`, 10.60%); 16×12×12 M даёт `22853.628` (ошибка `209.697 mm³`, 0.93%). Это один успешный refinement-тест, не полное исследование сходимости.
- **CI #38283320162**, коммит `30a665e9971f490fac8c554349abd6e83e739462`, https://github.com/Mika-dot/Cad/actions/runs/38283320162 — **PASS** чтение 25 BMP, увеличенных ×16 M-карт и изображений материала, Windows/Linux.

## Долги и точный scope для продолжения

1. Численно сравнить **финальные формы** в оригинальном `FEM_Voxel` Python SIMP/OC и новом FVM генераторе на эквивалентной постановке. Матрицы и стержень уже совпали, но итоговые методы оптимизируют разные переменные — этот пункт не зачёркивать.
2. Исследовать сходимость FEM-решения по `8×6×6 → ...` и регуляризации `epsilon_F/E_min`, а не только аппроксимации М-образов.
3. Проверить реакции/нагрузки при изгибе и распределённой несоосной силе, узловые ошибки напротив аналитики/Code_Aster.
4. Ввести общий `interface/preserve/avoid` для произвольных поверхностей и настоящий level-set-оператор нормальной скорости с доказанной shape derivative; затем adjoint.
5. Дополнительно провести данные sensitivity consistency: оценить производные на нескольких h и сравнить predictive mechanical slope с повторным расчётом.
