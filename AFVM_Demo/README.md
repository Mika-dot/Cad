# AFVM Demo — Adaptive Functional-Voxel Modeling

Отдельный исследовательский демонстратор для проверки гипотезы кандидатской темы:

**«Теория адаптивных преобразований функционально-воксельного представления с сохранением локальных геометрических характеристик и R-функциональной алгебры».**

Это не новая версия основного DCad и не попытка заменить `Unified-CAD`. Проект намеренно сделан автономным. Визуальная часть следует старому направлению репозитория `Mika-dot/Cad`: .NET/OpenTK/OpenGL, орбитальная камера, mesh+scalar vertex layout. Исследовательское ядро новое.

## Что именно проверяет демонстратор

В области Ω строятся четыре представления одной геометрии `sphere - cylinder`:

1. **Exact** — аналитическое R-поле, эталон.
2. **Uniform FV** — регулярная сетка, в каждой ячейке хранится локальная линейная функция.
3. **Adaptive FV direct** — адаптивное дерево локальных функций с контролем локальной геометрической ошибки.
4. **Adaptive FV R-algebra** — сначала независимо дискретизируются `sphere` и `cylinder`; затем R-разность строится **только из их локальных ФВ-представлений**, после чего результирующее поле снова адаптируется. Общая аналитическая функция `sphere-cylinder` для построения этого варианта не используется; она применяется только при внешней оценке ошибки.

Именно вариант 4 является главным proof-of-concept.

### Функциональный воксель

В каждом leaf хранится

`L(x) = f(c) + grad(f,c) · (x-c)`.

Локальные геометрические характеристики нулевой поверхности задаются нормализованной плоскостью:

`n = grad/|grad|`, `d = (f(c)-grad·c)/|grad|`.

В демо коэффициенты хранятся в double, а не в 8-bit M-образах: сейчас проверяется математика адаптивных преобразований, без внесения ошибки кодирования изображения.

### Критерий уточнения

На center/corners/face-centers сравниваются исходное поле и локальная функция. Ошибка переводится в размерность длины:

`e ≈ |f(x)-L(x)| / |grad f(x)|`.

Уточняются только узлы около нулевой поверхности. Поэтому `h_i` различается по пространству.

### R-функции

Принята конвенция `f <= 0` внутри тела.

- union: `f + g - sqrt(f²+g²)`
- intersection: `f + g + sqrt(f²+g²)`
- difference A\B: `f - g + sqrt(f²+g²)`

Градиент составной локальной функции вычисляется цепным правилом. Это позволяет сохранять не только знак/геометрию, но и локальные нормали.

## Запуск

Требуется .NET 8 SDK и OpenGL 3.3+.

```powershell
dotnet restore AFVMDemo.sln
dotnet run --project .\src\AFVMDemo\AFVMDemo.csproj -c Release
```

Только численные self-tests, без окна:

```powershell
dotnet run --project .\src\AFVMDemo\AFVMDemo.csproj -c Release -- --self-test
```

Параметры:

```text
--tol 0.025           геометрический допуск адаптации
--depth 6             максимальная глубина adaptive tree
--uniform-depth 5     регулярная сетка 2^depth на ось
--mesh-res 48         разрешение только визуального marching-tetrahedra mesh
```

## Управление

- `1` — аналитический эталон
- `2` — uniform FV
- `3` — adaptive FV, построенный напрямую
- `4` — adaptive FV, полученный R-алгеброй дискретизированных операндов
- `G` — adaptive leaf boxes варианта 4
- `W` — wireframe
- `H` — раскраска по ориентации нормали
- `F` — reset камеры
- мышь ЛКМ — вращение, колесо — zoom

## Что считать подтверждением гипотезы

Программа печатает:

- количество ячеек uniform grid;
- число adaptive leaves и surface leaves;
- RMS/max геометрическую ошибку относительно аналитического R-поля;
- среднюю/max ошибку направления локальной нормали.

Первый практически полезный результат — когда модель №4 имеет контролируемую ошибку, близкую к №3, при числе leaf существенно ниже регулярной сетки.

## Что этот демо пока НЕ доказывает

- нет строгой теоремы сходимости;
- `Restrict` сейчас простейший усредняющий оператор, а не оптимальный оператор редукции;
- octree используется как удобная реализация неоднородной области, а не объявляется научной новизной;
- нет M-образов и квантизации;
- нет полного набора ФВ-арифметики;
- нет доказательства коммутативной диаграммы `P(R(F,G)) ≈ R(P(F),P(G))` для произвольных функций;
- визуальный mesh строится marching tetrahedra и не является частью научной новизны.

Следующий научный этап описан в `docs/SCIENTIFIC_NOTE.md`.
