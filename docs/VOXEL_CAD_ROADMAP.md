# План развития VoxelСad

План отделяет работающий occupancy-прототип от будущих подсистем. Новая
функция добавляется только вместе с тестом, измерением ресурсов и описанием
единиц.

## Проверенное состояние

Сейчас `VoxelСad` использует `HashSet<(int X, int Y, int Z)>` как разреженную
бинарную сетку. Реализованы:

- аналитическая растеризация базовых тел;
- union, difference и intersection;
- dilation/erosion с соседствами 6, 18 и 26;
- удаление малых связных компонент;
- Gyroid, Schwarz-P и BCC occupancy;
- JSON-сценарии и headless CLI;
- greedy-объединение внешних граней при экспорте STL.

В текущем коде нет SDF, adaptive octree/VDB, mesh voxelizer, multi-material
ячеек, GPU backend или полноценного solid FEM.

## Этап 1. Зафиксировать базовый kernel

Работа:

1. добавить unit-тесты объёма и границ для каждой primitive;
2. сделать неизвестную JSON-операцию ошибкой, а не предупреждением;
3. валидировать `voxelSize`, размеры, радиусы и обязательные параметры;
4. добавить round-trip тест JSON → voxels → STL audit;
5. создать benchmark runner.

Готово, когда неверный сценарий всегда завершается ненулевым кодом, а
результаты валидных сценариев детерминированы.

## Этап 2. Общий интерфейс сетки

Ввести `IVoxelGrid`, не меняя результат существующих операций:

- `HashSetVoxelGrid` оставить эталонной реализацией;
- добавить sparse bricks 8³ или 16³ с bitset occupancy;
- выполнять morphology и meshing по bricks;
- хранить явное преобразование grid ↔ millimetres.

Готово, когда одинаковый JSON даёт одинаковый набор занятых координат и
одинаковый STL для двух backend-реализаций.

## Этап 3. Импорт mesh

Работа:

1. читать треугольный STL через единый mesh I/O;
2. проверять degenerates, holes, duplicate faces и winding;
3. реализовать детерминированный surface/interior voxelization;
4. определить поведение для открытых mesh.

Готово, когда набор тестовых STL имеет ожидаемые bounds, occupied volume и
число компонент при нескольких `voxelSize`.

## Этап 4. SDF как отдельный backend

SDF нельзя подменять бинарной occupancy. Для него нужны отдельные типы и
операции:

```text
union        min(dA, dB)
intersection max(dA, dB)
difference   max(dA, -dB)
offset       d - r
shell        abs(d) - thickness / 2
```

Минимальный объём этапа: narrow-band storage, redistance, field CSG, normals
и Marching Cubes. Dual Contouring и adaptive storage рассматриваются после
проверки базового SDF.

Готово, когда ошибка поверхности измеряется относительно аналитических sphere,
box и cylinder, а не оценивается только по картинке.

## Этап 5. Обмен с FEM_Voxel

Сетка геометрии и расчётные поля должны иметь общий metadata-контракт:

- размер и origin сетки;
- `voxelSize` и единицы;
- axis order;
- material/design mask;
- fingerprint геометрии;
- density, stress и displacement с явно указанной формой.

Текущий `FEMBridge` со стержнями между центрами ячеек остаётся демонстрацией и
не считается solid FEM.

Готово, когда один сохранённый расчёт можно сопоставить с исходной сеткой без
эвристик и вывести повторно с теми же координатами.

## Обязательные измерения

Для каждого backend и размера задачи сохранять:

| Метрика | Зачем |
|---|---|
| Число занятых ячеек | Контроль эквивалентности |
| Peak RAM | Стоимость representation |
| Время build/CSG/morphology | Сравнение операций |
| Время и число треугольников STL | Стоимость экспорта |
| Bounds и occupied volume | Геометрическая регрессия |
| Число компонент | Контроль связности |

Минимальные профили: плотная модель 64³/128³/256³ и разреженные модели с
одинаковым числом занятых ячеек при разных spatial extents.

## Не включать до завершения этапов 1–5

GPU, adaptive VDB, multi-material, manufacturing constraints и новые lattice
families не должны добавлять ещё один несовместимый grid type. Сначала нужны
общий контракт, эталонные тесты и измеримый выигрыш относительно
`HashSetVoxelGrid`.
