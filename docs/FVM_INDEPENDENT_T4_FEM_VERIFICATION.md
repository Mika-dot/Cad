# Независимая проверка экспортированного STL: Python T4 FEM против C# Hex8

Дата: 14 октября 2026 г. Ветка: \`feature/fvm-generative-mechanics\`.

## Что именно реализовано

\`experiments/FvmGenerativeDemo/independent_tetra_fem.py\` —
второй, полностью независимый конечно-элементный решатель.
Не использует ни C# Hex8 stiffness, ни FVM jet, ни R-функциональные
операторы оптимизатора.

**Вход:** экспортированная модель \`optimized.stl\`,
JSON-сцена с физическими опорами и ориентированными нагруженными
STL-патчами (MPa); фоновые разрешения T4 сетки.

**Физическая модель:** линейная изотропная упругость,
малые перемещения, 3D четыре узла на тетраэдр, три
степени свободы на узел, \`K u=f\`. Каждая прямоугольная
ячейка фоновой сетки независимо разбивается на 6 линейных
тетраэдров. Составляется разреженная матрица жёсткости
через NumPy/SciPy. Фиксируются узлы, попавшие в
реальные аналитически заданные \`fixed\` тела.

Материал определяется **не из 5-М/FVM изображения**,
а из фактического STL методом пересечения независимого
луча \`+X\` с треугольниками модели. Доступны два режима:

- \`--volume-quadrature 1\` — один центр тяжести T4,
  материал либо есть, либо его нет; именно такой результат
  показывает наиболее сильную сеточную зависимость.
- \`--volume-quadrature 4\` — симметричная положительная
  квадратура материала T4 (точки с барицентрическими
  координатами 0.585410..., 0.138196...).
  Доля материала в пересечённом тетраэдре
  \`rho_e\` принимает 0, 0.25, 0.5, 0.75 либо 1.

Матрица одного тетраэдра (из миллиметров и МПа):

\`\`\`text
J = [ X1-X0, X2-X0, X3-X0 ]
V_e = |det J|/6
B_e = gradients of four linear T4 shape functions
D = isotropic Hooke 6x6 matrix
K_e = V_e * (rho_e + epsilon*(1-rho_e)) * B_e^T D B_e
epsilon=10^-4
stress = D*B_e*u_e
von_Mises = sqrt(1/2*((σxx-σyy)^2+...)+3*(τxy^2+τyz^2+τxz^2))
\`\`\`

STL-нагрузка передаётся в FEM посредством
барицентрических shape-функций тетраэдра:
каждый ориентированный нагруженный треугольник
делится на мини-треугольники и их давления
интегрируются по трём точкам. Сумма узловых сил
контролируется по точному \`p × A × n\`,
полная реакция \`R = Ku - f\` проверяется
независимо от Hex8.

**ВАЖНО:** это всё ещё *immersed/background mesh*
с регуляризованной пустотой, **а не volume-conforming
сетка из тетраэдров, полученная по точным фасетам STL**.
Никакой гарантированной оценки погрешности (тем более
сертификации промышленной прочности) пока нет.

## Аналитический тест, который обязан пройти

Стержень длиной 100 мм, сечение 10×10 мм,
E=200000 МПа, Poisson=0.0,
закрепление при x=0, давление при x=100:
\`p=10 МПа\`.

Точные значения: \`F=1000 N\`, \`Rx=-1000 N\`,
\`u_max=0.005 mm\`, \`σ_VM=10 MPa\`,
\`V=10000 mm³\`.

[Independent T4 #38524416057](https://github.com/Mika-dot/Cad/actions/runs/38524416057):
на 4×2×2, 8×3×3 и 12×4×4 background-сетках
достигнуты \`u=0.005000000\`,
\`0.005000000\` и \`0.005000268\` мм;
\`Rx=-1000.000000 N\` во всех случаях;
\`σ_VM=10.00000, 10.00000, 10.00798 MPa\`.
Это проверяет сам T4 solver, но не точность произвольного STL.

## Что показал настоящий оптимизированный STL

Сцена: \`multi_scene_surface_pressure.json\`;
исходные три тела и одна запретная область.
Две ориентированные STL-грани на торце
нагружаемого бокса: площадь 256 mm²,
давление 0.5 MPa, \`Fx=128 N\`.
C# \`--free-topology --iterations 2\` реально
создал \`optimized.stl\`.

Независимый **T4 при классификации по центру тетраэдра**:

| Величина | T4 10×7×6 | T4 14×10×8 |
|---|---:|---:|
| Фактических тетраэдров | 2520 | 6720 |
| Тетраэдров с материалом | 441 | 1218 |
| Оценка объёма материала, mm³ | 35154.0 | 36409.5 |
| Максимальное σ_VM, MPa | 2.7857 | 3.9806 |
| Максимальное перемещение **узлов материала**, mm | 0.000589 | 0.000362 |
| Полная реакция, N по X | -128 | -128 |
| Узловая нагрузка на ersatz-only узлах | 4.28% | 9.73% |

Данные: [CI #38524691172](https://github.com/Mika-dot/Cad/actions/runs/38524691172).

Для сравнения: **C# бинарный Hex8** на основной
фоновой сетке той же сцены:
\`V_binary≈36828 mm³\`, \`VM_binary≈1.446 MPa\`,
\`u_binary≈0.000269 mm\`.

Это серьёзное **несогласие дискретизаций**,
а не повод заявлять, что «тетраэдры точнее».
Пиковые напряжения чувствительны к тому, какие
пограничные ячейки заполнены и как к ним приложено
давление. На более тонкой T4 сетке после прямого
классификатора по центру примерно 9.7% суммарной
модульной узловой нагрузки оказалось на узлах,
к которым не примыкает материальный T4.
Это отдельный критический индикатор
неразрешённых cut-cells.

**Также исправлена ошибка отчётности:** первоначально
\`maxDisplacement\` считался в том числе на отдалённых
background-узлах виртуально пустых элементов и достигал
0.008–0.011 мм. Это не перемещение реального
твёрдого тела. Теперь отдельно выводятся
\`maxDisplacementMm\` для материальных узлов и
\`maxErsatzBackgroundDisplacementMm\` для
всего искусственного домена.

## Проверка двух дискретизаций

\`compare_fem_discretizations.py\` строит
\`fem_cross_check.json\` со значениями C# Hex8
и T4 на двух сетках, отклонениями, связностью
тетраэдральных материальных компонентов и
частью давления, приходящейся на пустые узлы.

При отсутствии численного согласия
\`--require-agreement\` должен выдавать
ненулевой код и диагностическое сообщение.
Даже при PASS этот тест остаётся **только
скрининговой проверкой**, не сертификацией.

## Дальнейшие недоделки, которые нельзя скрывать

1. Строго согласованное пересечение
   тетраэдров с реальной STL-поверхностью,
   вместо выборки в 1/4 точках.
2. Независимая conforming tetra-сетка, согласованная
   с конкретными реальными отверстиями,
   фасками и поверхностями контакта.
3. Сеточное исследование \`h->0\` на самой
   STL-сетке, исключающее физические
   сингулярности точечных фиксаторов.
4. Проверка гидравлического контакта,
   трения, реального крепежа и вибрации,
   анизотропии печати, нагрузочных историй.

Нельзя представлять результат работы компьютера как
доказанную глобальную минимальность формы или её
подтверждённую промышленную несущую способность.
