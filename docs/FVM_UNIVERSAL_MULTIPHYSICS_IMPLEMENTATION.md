# Универсальный ФВМ × FEM: практическая реализация для 2–32 геометрических областей

Дата: 13.10.2026. Ветка: feature/fvm-generative-mechanics.
**Статус: исполняемый исследовательский прототип, а не промышленно аттестованная САПР.**

Этот документ описывает только фактически написанный код. Более широкий математический замысел — в FVM_MULTIPHYSICS_GENERATIVE_DESIGN.md.

## 1. Что реализовано

Можно задать от 2 до 32 геометрических областей с уникальными ID и ролью:

- **fixed** — закреплённое тело (несколько закреплений);
- **load** — нагруженное тело;
- **anchor** — обязательная геометрия без собственного обязательного закрепления;
- **obstacle** — исключённый объём, куда запрещено вести соединитель, с пользовательским clearance.

Геометрия — вложенная CSG-композиция sphere, box, ellipsoid, capsule, cylinder, torus, union, intersection, difference. **Тип mesh** импортирует любое корректное замкнутое тело в ASCII/Binary STL в пределах ограничений импортера (4–200 000 треугольников). При импорте проверяется, что каждое ребро принадлежит ровно двум граням, а расстояние до поверхности/принадлежность объёму вычисляются с пространственным BVH-ускорением. STEP/BREP напрямую пока не импортируется: сначала экспорт в STL.

Каждое требуемое тело имеет **seed** — опорную точку внутри объёма. Dijkstra ищет 3D-путь с 26 соседями от новой точки к уже построенной сети. Кандидатный отрезок дискретно проверяется на заданный зазор до всех препятствий и запас на радиус будущей перемычки; точки упрощаются только при сохранении безопасности на прямых сегментах. **Это приближённая маршрутизация, не глобальная оптимизация сети Штейнера.**

Итоговая неявная функция:

F_keep = max(F_body_1, ..., F_body_N, F_bridge_1, ..., F_bridge_K)

F_design = min(F_keep, -F_obstacle_1-clearance_1, ..., -F_obstacle_M-clearance_M).

Знак F>0 означает материал; F=0 — граница. Конкретная форма каждой ветви задаётся капсулами, её радиус — переменная оптимизации. Речь идёт о **согласованном изменении одного поля F**: пять М-образов (локальные нормированные коэффициенты F и её пространственных производных) пересчитываются вместе. Никакого предписанного процента удаляемых вокселей нет.

## 2. Реальные физические решатели

Все используют одну геометрию и тот же регуляризованный материал, но физические состояния остаются отдельными.

| Расчёт | Реально реализовано | Ограничение |
|---|---|---|
| Статика | Изотропный 3D Hex8 FEM, K·u=f, 2×2×2 Gauss, разные loadCases, несколько fixed-областей | Линейная упругость, сглаженная граница материала, объёмные узловые нагрузки |
| Колебания | Первая собственная частота из Kφ=ω²Mφ посредством обратных итераций | Одна приближённая мода; возможны ложные моды эрзац-материала |
| Вибрация | Первомодовая гармоническая реакция с частотой и демпфированием | Не полный многомодовый частотный спектр |
| Удар | Реальное интегрирование M·ü+C·u̇+K·u=f(t) схемой Newmark β=1/4, γ=1/2; силовой полусинус | Не контактный удар, без пластичности и разрушения |
| Теплопроводность | 3D стационарная матрица K_T, две области с фиксированными относительными температурами, эквивалентная проводимость W/K | Без конвекции/излучения, не переходный тепловой процесс |
| Термоупругость | T→ε_th=α(T−T_ref)I→эквивалентная нагрузка→второй 3D FEM, термонапряжения/перемещения | Односторонняя связь, модуль E не зависит от T |
| Усталость | Первичная проверка через кривую Basquin N=N_ref(S_ref/S_a)^m и damage=cycles/N | Не многоосная fatigue/rainflow, не подтверждённый ресурс |

**Недоступно**: настоящий контактный удар, нелинейная пластичность, устойчивость/buckling, полная многочастотная FRF, циклическое накопление по истории напряжений, полная сеточная сходимость, произвольный STEP без преобразования, промышленные граничные условия по выбранной поверхности.

Механика работает в мм, Н, МПа, секундах; масса для динамики преобразуется из кг/мм³ в Н·с²/мм делением на 1000. Теплопроводность из W/(м·К) в W/(мм·К) делением на 1000. Это принципиально для корректных частот и импульсов.

## 3. Как выполняется оптимизация

1. Сформировать CSG тело и безопасные ветви.
2. Пересэмплировать непрерывную F и её градиенты в пять М-образов.
3. Для каждого сценария решить K(F_M)u=f, вычислить объём, максимум по Мизесу, перемещения, реакции.
4. Для заданных физических ограничений запустить дополнительный модальный, ударный, гармонический, тепловой, термоупругий и усталостный блоки.
5. Вычислить сопряжённые чувствительности объёма/податливости в точках Гаусса; производные реконструированного F_M по радиусам ветвей — центральной разностью двух M-моделей, без повторного FEM для каждого параметра.
6. Сформировать направление облегчения; пробовать меньшие шаги при нарушениях.
7. Кандидат принимается, только если **объём уменьшился**, все активные критерии прошли, несколько тел остались в одной дискретно связной компоненте, keepout не заполнен в проверенных точках, а **повторная проверка напрямую по F на той же FEM-сетке** подтверждает результаты.
8. Экспортировать initial.stl, optimized.stl, routes.csv, metrics.csv и summary.json. STL строится из пяти M, а независимый Python-валидатор требует watertight + oriented + connected.

**Геометрическая и физическая строгость:** положительный дискретный путь через центры M-ячеек не доказывает сплошность реальной поверхности между ними. STL-проверка даёт дополнительную независимую топологическую проверку; она не подтверждает прочность печатной детали. M/direct-F на одной сетке не заменяет сходимость FEM при уточнении.

## 4. Файлы проекта

- experiments/FvmGenerativeDemo/UniversalScene.cs — JSON, CSG, obstacle routing, полное функциональное поле.
- experiments/FvmGenerativeDemo/ImplicitMesh.cs — input binary/ASCII STL, ускоренная геометрическая проверка.
- experiments/FvmGenerativeDemo/UniversalDesign.cs — все нагрузки, ограничения, sensitivities и line search.
- experiments/FvmGenerativeDemo/HexFemMultiphysics.cs — modal, Newmark, thermal, thermoelastic, harmonic response.
- experiments/FvmGenerativeDemo/HexFem.cs — оригинальный проверенный 3D Hex8 FEM.
- experiments/FvmGenerativeDemo/TwoSphereDesign.cs — сохранён прежний режим двух сфер и общий качественный STL exporter.
- experiments/FvmGenerativeDemo/multi_scene_6_bodies.json — 6 разных тел, 2 запрещённых объёма, 2 нагрузочных случая и включённые физические критерии.
- experiments/FvmGenerativeDemo/multi_scene_forced_detour.json — непроходимый прямой маршрут, обход обязателен.
- experiments/FvmGenerativeDemo/multi_scene_imported_stl.json — произвольный STL как входная закреплённая геометрия.
- experiments/FvmGenerativeDemo/validate_stl.py — независимый контроль итогового STL.

## 5. Как запустить

Из корня репозитория:

```powershell
git switch feature/fvm-generative-mechanics
dotnet build experiments/FvmGenerativeDemo/FvmGenerativeDemo.csproj -c Release --warnaserror

dotnet run --project experiments/FvmGenerativeDemo -c Release -- --multi-scene experiments/FvmGenerativeDemo/multi_scene_6_bodies.json --iterations 2 --out output/multi-six

dotnet run --project experiments/FvmGenerativeDemo -c Release -- --multi-scene experiments/FvmGenerativeDemo/multi_scene_forced_detour.json --iterations 1 --out output/forced-detour

python experiments/FvmGenerativeDemo/validate_stl.py output/multi-six/initial.stl output/multi-six/optimized.stl
```

Пример бинарного STL-импорта:

```powershell
python experiments/FvmGenerativeDemo/make_input_binary_stl.py experiments/FvmGenerativeDemo/input_cube_ascii.stl experiments/FvmGenerativeDemo/input_cube_binary.stl
dotnet run --project experiments/FvmGenerativeDemo -c Release -- --multi-scene experiments/FvmGenerativeDemo/multi_scene_imported_stl.json --iterations 1 --out output/imported
```

Статические, модальные, тепловые и ударные пороги задаются в JSON. Если исходная форма нарушает требования, запуск завершается FAIL; если после оптимизации нет допустимого уменьшения массы, алгоритм сообщает STOP вместо недоказанного утверждения об оптимуме.

## 7. Незакрытые инженерные вопросы

Сеточная сходимость FEM, точное интегрирование по границе, истинные поверхностные BC, напряжения в сингулярностях, физические испытания удара, многомодовые вибрации, контакт/пластичность, настоящая усталость, buckling и сравнение с независимым SIMP/level-set на эквивалентной задаче. Научная новизна именно согласованной ФВМ-проекции градиентов **пока не доказана**.
