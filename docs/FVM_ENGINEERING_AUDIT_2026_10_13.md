# Аудит инженерных расчётов и самостоятельного построения ферм

Дата: 13.10.2026. Рабочая ветка: feature/fvm-generative-mechanics. Код: experiments/FvmGenerativeDemo.

## 1. Что даёт и чего не даёт исходная FEM_Voxel

В ветке FEM_Voxel оригинальный openscad_gen/optimizer.py использует настоящую плотностную топологическую оптимизацию SIMP/OC в проектной области: относительная плотность каждого конечного элемента может изменяться, учитываются механические чувствительности, фильтр, Heaviside, фиксированный материал и связность. Это позволяет изменять распределение материала и появление отверстий/несущих перемычек на сетке.

При этом оригинальный README прямо предупреждает: физические роли fix, force, preserve, avoid надёжно задаются аннотациями GD_ENTITY. Автоматическая интерпретация порядка OpenSCAD-объектов является лишь эвристикой. Из геометрии физическое закрепление нельзя определить однозначно.

В новой C# реализации уже автоматически создаются основные маршруты между 2–32 обязательными объектами, а optional autoTruss создаёт дополнительные пространственные диагонали. Их толщина изменяется в рамках FVM/FEM оптимизации. Точки seed можно не задавать вручную, если внутреннюю точку удаётся найти из CSG/STL. Тем не менее это пока **параметрический синтез сетки несущих рёбер, а не свободная плотностная или level-set оптимизация**, аналогичная SIMP/OC оригинала. Нельзя утверждать, что все возможные ферменные конфигурации уже оптимизируются.

## 2. Проверенная постановка

Одна непрерывная функция F(x,y,z)>0 описывает материал. Из неё и пространственного градиента строятся пять согласованных M-гиперплоскостей. CSG union и difference, маршруты и новые диагональные раскосы объединяются в ОДНО поле F, пересэмплируемое в пять M. Входная STL-грань интерполируется и содержит ошибку геометрии, а min/max CSG имеет недифференцируемые стыки.

3D Hex8: K(F)u=f, восьмиточечная Gauss-квадратура, изотропная линейная упругость, сглаженный ersatz материал, диагонально-предобусловленный PCG. Это не точное интегрирование по поверхности STL. Механические ограничения по напряжениям/перемещениям проверяются на M и напрямую по F на ОДНОЙ фоновой сетке. Ни одна из проверок сама по себе не доказывает сходимость реальных напряжений.

## 3. Конкретные найденные и исправленные ошибки

- Связность: поиск из всех фиксированных компонент сразу мог принять несоединённые опоры за связное тело. Начало поиска теперь одно, и требуется связь со всеми обязательными объектами.
- Direct-F проверка геометрической связности раньше фактически использовала M-бинарную маску. Теперь принадлежность проверяется независимо для direct F и M.
- Маршрутизация: раньше ветвь могла подключиться к сеточному узлу, который был удалён при упрощении старой полилинии. Теперь точки потенциального присоединения сохраняются в выводимой геометрии.
- Закреплённые и нагруженные FEM-узлы: на фиксированной степени свободы RHS зануляется. Накладывать туда ненулевую силу без диагностики физически некорректно. Добавлен явный FAIL для таких нагрузочных случаев.
- Мультифизика: раньше удар и одномодовая гармоника вычислялись только по первому load case. Теперь берётся худший отклик по всем заданным случаям. Введён отдельный максимум ударного von Mises, помимо максимума импульсного перемещения.
- Масса: прежняя HexFem.MassKg была всегда рассчитана для стали 7850 кг/м³ даже с другим входным материалом. Теперь передаётся densityKgMm3 из сцены; в старых эталонах сохранена плотность стали по умолчанию.
- STL input: прежняя проверка парности граней по ребру не отвергала плохую ориентацию и несколько несвязанных оболочек. Добавлены тесты согласования направлений, одной компоненты и ненулевого объёма.
- STL export/validation: C# после увеличения точности экспортировал G17, однако Python продолжал округлять вершины до 0.0001 мм, порождая ложные «degenerate triangles». Теперь обе проверки используют точность 1e-9 мм. Нужна итоговая регрессия всех трёх сценариев.

## 4. Критические замечания о физических расчетах

В статике проверены реакция и невязка свободных FEM степеней свободы, однако физически локальные пик-напряжения нельзя надёжно получить без сходимости по сетке, сглаживанию и способу приложения нагрузок. Фиксация сейчас — объёмное u=0, не расчёт контакта, болтов или упругой опоры.

Модальный блок рассчитывает приближённую первую собственную частоту. Малый собственный residual НЕ равен малой физической ошибке частоты на грубой сетке. Добавлена задача консольной балки с известной формулой Euler-Bernoulli и более подробным Hex8 мешем, чтобы измерять эту ошибку, а не просто проверять положительный eigenvalue.

Импульс — линейный силовой полусинус и Newmark (beta=1/4, gamma=1/2); это НЕ контактный удар, пластичность или разрушение. Harmonic response — первая мода, а не полный спектр. Термоупругость — последовательная стационарная тепловая задача, без E(T) и thermal feedback. Fatigue — предварительный Basquin screening по аппроксимации амплитуды, а не многoосная оценка rainflow. Ни один из этих модулей нельзя объявлять сертифицированной прочностью.

Единицы: N, mm, MPa, секунды; mass for dynamic N*s²/mm = mass in kg / 1000. Thermal conductivity W/(mm K)=W/(m K)/1000. Mass kg = Volume mm³ * density kg/mm³.

## 5. Что делает autoTruss

Если в JSON включить autoTruss=true, пользователь по-прежнему указывает исходные фигуры и физические роли (fixed, load, anchor), но не задаёт вручную центральные линии рёбер или раскосы. Система автоматически строит маршруты, а на безопасных достаточно длинных сегментах предлагает диагональные боковые элементы с точками (a+b)/2 ± trussOffsetMm*n, где n перпендикулярна оси исходного соединения. Раскосы являются отдельными FVM-параметрами радиуса и проходят FEM-проверки. Если геометрическая точка seed отсутствует, она подбирается автоматически, но для очень тонких или сложных полостей может понадобиться ввод seed пользователем.

Это первая практическая эвристика автосинтеза фермы. Она НЕ строит гарантированно минимальную свободную топологию и не соответствует полной SIMP/OC постановке оригинальной FEM_Voxel.

## 6. Воспроизведение и критерии завершения

Из корня репозитория (после git switch feature/fvm-generative-mechanics):

    dotnet build experiments/FvmGenerativeDemo/FvmGenerativeDemo.csproj -c Release --warnaserror
    dotnet run --project experiments/FvmGenerativeDemo -c Release -- --multiphysics-self-test
    dotnet run --project experiments/FvmGenerativeDemo -c Release -- --multi-scene experiments/FvmGenerativeDemo/multi_scene_auto_truss.json --iterations 1 --self-test --out output/auto-truss
    python experiments/FvmGenerativeDemo/validate_stl.py output/auto-truss/initial.stl output/auto-truss/optimized.stl
    python experiments/FvmGenerativeDemo/validate_keepouts.py experiments/FvmGenerativeDemo/multi_scene_auto_truss.json output/auto-truss/routes.csv output/auto-truss/initial.stl output/auto-truss/optimized.stl

В GitHub Actions также должны пройти Windows, Ubuntu, независимое сравнение матрицы элемента с оригинальным Python FEM_Voxel, отрицательные тесты для ошибочных закреплений и визуально-независимая геометрическая проверка STL. До получения финального CI PASS нельзя утверждать завершённую верификацию текущего коммита.

## 7. Что осталось приоритетом P0

Настоящий свободный топологический оптимизатор распределения F в доступной проектной области, а не только граф с раскосами; сравнение с оригинальным SIMP/OC на тождественной постановке; независимый FEM по экспортированной STL и сеточная сходимость h_FEM, h_M, epsilon, E_min; реальные поверхностные нагрузки, упругие/контактные закрепления, динамический спектр и многоосная усталость. Автоматически угадывать физические опоры из одной формы без инженерных данных запрещено.
