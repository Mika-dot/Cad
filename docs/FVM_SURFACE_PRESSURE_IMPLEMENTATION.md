## 1. Исправляемая физическая модель

До этого внешний силовой вектор `forceN` распределялся между всеми
попавшими внутрь обязательной геометрии FEM-узлами. Он имел правильную
равнодействующую, но **не моделировал физическое поверхностное давление**.
В частности, дискретное распределение могло зависеть от того, какие
узлы попали внутрь нагруженного объёма. Теперь сохраняется старый
режим совместимости и добавляется **отдельный режим истинного
поверхностного интегрирования**.

Для известной внешней нагрузки (поверхность Γ, давление p):

```math
f_a^{\Gamma} = \int_{\Gamma} N_a(x)\,p(x)\,n(x)\,d\Gamma
```

где `N_a` — 3D Hex8 функции формы, `p` — давление в
Н/мм² = МПа, `n` — внешняя единичная нормаль к нагруженному
треугольнику и `f_a` — узловая сила, Н.

**Два реально работающих интегратора:**

1. `HexBoundaryPressure(Face,PressureMpa)` — равномерное давление
   на внешнюю прямоугольную грань фоновой FEM-сетки:
   `xmin/xmax/ymin/ymax/zmin/zmax`. Для неё применяется 2×2
   Gauss-интегрирование квадрата. Это **именно граница всего
   background Hex8**, а не произвольный CSG/STL.
2. `HexTrianglePressure(A,B,C,PressureMpa)` — поверхность,
   представленная реальными ориентированными треугольниками.
   Нормаль определяется **порядком обхода** `(B−A)×(C−A)`.
   Для каждого треугольника используется 3-точечное симметричное
   барицентрическое интегрирование; соответствующие узловые
   функции формы вычисляются в 3D Hex8, содержащем точку Гаусса.
   Треугольники не обязаны совпадать с гранями background-элементов.

Для треугольника постоянного давления:

```text
A = |(B-A) x (C-A)| / 2
F_exact = p * A * normalize((B-A) x (C-A))
F_Gauss = sum over 3 points of [p * (A/3) * n]
```

Сумма всех интерполированных узловых сил **сохраняет равнодействующую**,
поскольку сумма функций формы Hex8 в каждой точке равна единице.
Но распределение между соседними узлами приближённое, если
треугольник пересекает границы background-элементов. Для независимой
оценки погрешности нужно уточнять как **исходную STL-поверхность**,
так и FEM-сетку; одного совпадения равнодействующей недостаточно.

## 2. Входная нагрузочная CAD-поверхность

`SurfacePatchStl.Read(path,p)` читает реально существующий
**ASCII или binary STL-файл**. Это **открытая нагружаемая поверхность**,
а не отдельное замкнутое тело: она может состоять из двух треугольников.
Число граней, вырожденность, формат координат и ориентацию
проверяет входной код. Полная перевёрнутая нормаль должна
быть отвергнута ещё до запуска FEM.

Дополнительные поля JSON-сцены (пример в репозитории):

```json
{
  "loadCases": [
    {"name": "pressure-only", "forcesN": {}}
  ],
  "surfacePressurePatches": [
    {
      "loadCase": "pressure-only",
      "bodyId": "loaded-box",
      "stlFile": "pressure_load_box_end.stl",
      "pressureMpa": 0.5
    }
  ]
}
```

Это **дополнительные поля** полного файла
`multi_scene_surface_pressure.json`; требуемые `bounds`,
`bodies`, `obstacles`, `material` и `limits` также
необходимо задавать.

Для конкретного торца тестового параллелепипеда:
размер **16×16 мм**, площадь **256 мм²**,
p=**0.5 МПа**, следовательно интегральная сила
**128 Н** по нормали +X. Источник — два правильно
ориентированных STL-треугольника на поверхности
`x=72 mm`. Отдельные `forceN` отсутствуют.

В CSG/FEM реализация передаёт список `trianglePressures`
в основной HexFem и вычисляет ожидаемую физическую
равнодействующую из **всех треугольников каждого loadcase**.
Эта же нагрузка передаётся при дополнительных FEM-пересчётах
`direct-F`, бинарной модели и уточнённой сетки в
`FreeTopologyDesign`; исходная распределённая сила больше
не подменяется `forceN / node_count`.

## 3. Когда поверхностная нагрузка считается физически допустимой

Входная проверка до FEM требует:

- `loadCase` существует, `bodyId` обозначает реальное
  незакреплённое обязательное тело, pressure конечна и не равна нулю;
- все вершины лежат внутри заданных `bounds`;
- центры треугольников находятся на границе именно
  выбранной CSG/STL-геометрии в допуске исходного шага;
- направление нормали соответствует **наружной стороне**
  выбранной обязательной детали;
- конструкция после построения сохраняет эти треугольники
  на **экспонированной границе материала**: немного внутри
  по отрицательной нормали находится материал, снаружи —
  пустота. Контроль выполняется для пяти М-образов и direct F.

Это **дискретный контроль центра** каждого треугольника.
Он не является математической гарантией отсутствия
местного перекрытия на каждом квадратном микрометре.

**Теперь для свободной топологии реализована явная внешняя
контактная полость (актуально после обновления).**
Начальная плотность `rho≈0.90` ранее могла заполнить место перед
нагруженной поверхностью. Теперь она **не имеет права** его заполнить:
по каждому ориентированному STL-треугольнику автоматически формируется
полубесконечный наружный запретный контактный канал (с ограничением
по проекции на сам треугольник и боковым запасом).
Если `d=(x-A)·n` — ориентированное расстояние до плоскости, а
`e(x)` — минимальное подписанное расстояние до трёх рёбер
треугольника **в его плоскости**, то:

```text
F_contact(x) = max(-d(x), -e(x)-contactMargin)
F_total(x)   = min(F_existing(x), min_k F_contact,k(x))
contactMargin = 0.35 * fvmStepMm
```

Для `d>0` и `e>-contactMargin` материал удаляется;
для `d<0` нормальное защищённое тело сохраняется. Операция
вычисляется **и в поле ФВМ, и при проверке активности
производной**: оптимизация не может закрыть контакт
новой плотностью. Исходная STL нагрузки всё ещё
должна действительно описывать исходную наружную поверхность.

**Подтверждено реальным исполнением**:
[CI #38422695754](https://github.com/Mika-dot/Cad/actions/runs/38422695754),
Windows и Ubuntu PASS. В одной и той же сцене
`multi_scene_surface_pressure.json` — **3 исходные фигуры,
1 запретный объём, 128 Н внешнего давления, никакой ручной
фермы** — свободный пяти-М SIMP/OC принял 2 изменения,
объём сглаженного FEM уменьшился на **12.107%**, геометрический
STL на **16.636%**, бинарное FEM-напряжение **1.454 МПа**.
Градиенты проверены прямыми конечными разностями в 3 независимых
пространственных управляющих ячейках.

Регрессионно при явном JSON `"pressureContactVoid":false`
нагрузочная STL оказалась скрыта плотностным материалом и
программа ожидаемо отказалась выдавать проект. По умолчанию
`pressureContactVoid=true`.

Это инженерная непрерывная CSG-аппроксимация открытого
контактного доступа, **не доказательство непрерывного
зазора в любой точке STL**. Экспортированная поверхность
дополнительно проверяется независимым Python ray-casting,
а реальные контакты всё ещё требуют уточнения FEM-сетки.

## 4. Исправлен учёт реакций

При формировании граничных условий `u=0` RHS на
соответствующих степенях свободы обнуляется **только
для решения** матрицы. Реакцию следует получать из

```math
R_i = (K u)_i - f_i^{original}
```

а не из `Ku` за вычетом обнулённого RHS.
Отдельный `_appliedRhs` сохраняет исходные внешние
нагрузки до зануления зафиксированных степеней свободы.
Это принципиально при давлении на грань, которая
соприкасается с закреплённой областью.

## 5. Проверенные аналитические эталоны

3D консольный стержень:
L=100 мм, площадь поперечного сечения 100 мм²,
E=200000 МПа, ν=0.
Однородное торцевое давление p=10 МПа, F=1000 Н.

```text
аналитика: stress = F/A = 10 МПа
аналитика: u = F*L/(E*A) = 0.005 мм
аналитика: реакция Rx = -1000 Н
```

Все результаты реально подтверждены на **Windows и Linux**:

- внешний интеграл квадрата 2×2 Gauss: сетки
  `4×2×2`, `8×2×2`, `16×2×2`, результат
  `F=1000 N, Rx=-1000 N, u=0.005 mm`;
- интеграл по **2/8/32 реальным треугольникам** на
  сетках `4×1×1`, `8×2×2`, `16×4×4`,
  та же нагрузка и то же удлинение;
- чтение двух треугольников сначала из **binary STL**,
  затем из **ASCII STL**, одинаковая физика;
- комбинированные поверхности
  `xmax:10 MPa`, `ymax:1 MPa`, `zmin:2 MPa`
  должны создавать результирующие компоненты
  `Fx=1000, Fy=1000, Fz=-2000 N`, а реакции
  соответственно `-1000,-1000,+2000 N`.

[GitHub CI с аналитическими pressure-тестами](https://github.com/Mika-dot/Cad/actions/runs/38420106507):
Windows PASS, Ubuntu PASS.

[Интеграционный CSG/FVM FEM pressure тест](https://github.com/Mika-dot/Cad/actions/runs/38420819141):
3 реальных тела, одна запретная зона, одна полностью
поверхностная нагрузка, без искусственных внутренних сил;
**один принятый шаг**, сокращение сглаженного FEM-объёма
**0.11%**, STL-объёма **0.158%**.
Независимые валидаторы STL и запретных зон — PASS.
Экономия здесь мала; не следует подменять её прежними
значениями из более сильных объёмных нагрузок.

## 6. Запуск

```powershell
git switch feature/fvm-generative-mechanics
dotnet build experiments/FvmGenerativeDemo/FvmGenerativeDemo.csproj -c Release --warnaserror

# Проверить файл, нормали, поверхность и инженерные условия
dotnet run --project experiments/FvmGenerativeDemo -c Release -- --validate-scene experiments/FvmGenerativeDemo/multi_scene_surface_pressure.json

# Фактическая поверхность STL: p=0.5 MPa, 256 mm2, F=128 N
dotnet run --project experiments/FvmGenerativeDemo -c Release -- --multi-scene experiments/FvmGenerativeDemo/multi_scene_surface_pressure.json --iterations 1 --self-test --out output/pressure

python experiments/FvmGenerativeDemo/validate_stl.py output/pressure/initial.stl output/pressure/optimized.stl
python experiments/FvmGenerativeDemo/validate_keepouts.py experiments/FvmGenerativeDemo/multi_scene_surface_pressure.json output/pressure/routes.csv output/pressure/initial.stl output/pressure/optimized.stl
```

CI также специально отвергает ошибочный порядок обхода STL,
нестыковку имени нагрузочного случая, давление на `fixed`-тело,
нулевое давление и STL-поверхность, удалённую от указанного тела.
Отдельный отрицательный тест убеждается, что заглублённая
в плотностную область поверхность **не будет ошибочно
использована как внешняя traction**.

## 7. Нерешённые вопросы

Реально пригодная промышленная постановка должна ещё иметь:

- независимый STL/tetra FEM и сеточную сходимость
  `h_FEM` и размера исходных нагружаемых граней;
- произвольные `p(x,t)`, распределённые касательные
  traction и реальные столкновения/контактную динамику;
- выделение exposed pressure patch непосредственно на
  исходном CAD/STEP/BREP, а не только импорт выбранных
  STL-треугольников;
- сеточно-независимое подтверждение уже автоматически
  создаваемой внешней контактной зоны и точную интеграцию
  по реальной деформируемой STL-поверхности;
- нелинейность, болтовые контакты, анизотропию
  3D-печати и экспериментальную валидацию.

Завершение тестов pressure не делает любые прежние
упрощённые импульсные/усталостные модули
эксплуатационно достоверными.
