# Функционально-воксельное ядро DCad — этап 1

Ветка: `feature/functional-voxel-kernel`, база: `Unified-CAD`. Проект: `src/DCad.FunctionalVoxel`, проверки: `tests/DCad.FunctionalVoxel.Tests`.

## Математическая модель

Это **не occupancy voxel** и не обычный SDF. Представляется аналитическое поле `u=f(x_0,...,x_(n-1))` и его локальные геометрические характеристики в каждой точке регулярной решётки аргументов. В каждой точке `p` известны `f(p)` и `g_i=∂f/∂x_i`. Локальная функция:

```text
L(x,u) = a0*x0 + ... + a(n-1)*x(n-1) + a(n)*u + a(n+1) = 0

s       = sqrt(1 + sum_i g_i^2)
a_i     = -g_i/s             i=0..n-1
a_n     = 1/s
a_(n+1) = (sum_i g_i*p_i - f(p))/s

u(x) = -[a_(n+1) + sum_i a_i*x_i] / a_n
∂u/∂x_i = -a_i / a_n
```

Таким образом, для двух аргументов используются четыре М-образа, для трёх — пять. Числовой слой содержит один коэффициент локальной гиперплоскости на каждый воксель. Нормируется нормаль в расширенном пространстве аргументов и значения функции, но не свободный коэффициент. Операции над М-образами выполняются по восстановленным локальным функциям **без исходного аналитического выражения**.

Знак поля: `f >= 0` означает внутреннюю область. Величина поля не обязана быть подписанным расстоянием.

## Реализовано

| Компонент | Реализация | Проверка |
|---|---|---|
| Аналитические поля | `FunctionalField`, построитель выражений; скалярное значение, градиент, матрица Гессе средствами автоматического дифференцирования | полиномы, сфера, точные производные |
| Локальная функция | `LocalFunctionalPlane`: `n+2` коэффициента и обратное восстановление | касательная, градиент и единичная нормаль |
| М-образы | `FunctionalVoxelModel`: многоканальные массивы `double`, 1–4 измерения | размерность, восстановление в узлах |
| Упаковка | `EncodedMImages`: независимое масштабирование каждого канала, RGB24 (`0..16777215`) | максимальная ошибка по диапазону и обратный ход |
| R-алгебра Рвачёва | R0 и параметр `alpha` для объединения, пересечения, вычитания; вычисление градиента по цепному правилу | топология знака, численное сравнение аналитики с операциями над М-образами |
| Геометрические функции | плоскости, диск, шар, параллелепипед, цилиндр | тесты принадлежности |
| Проекция/перенос аргументов | `MapArguments` с произвольной аффинной матрицей, `Lift` | цепное правило до вторых производных |
| Дифференцирование | аналитически до второго порядка; по коэффициентам М-образов — первый порядок | полиномы |
| Численное интегрирование | метод трапеций вдоль оси, условие Коши в первом центре каждой строки | точная для линейного примера квадратная первообразная |
| Объём/площадь области | подсчёт положительных центров × мера ячейки | сходимость к объёму шара |
| Приближённая реконструкция между узлами | интерполяция локальных гиперплоскостей | линейная функция |
| Геометрическое выделение поверхности | `FunctionalIsoSurface.Extract` → общий `DCad.Core.Mesh3d`, согласованная тетраэдризация | замкнутость, winding, площадь и объём сферы |
| Базовый локальный поиск | `FunctionalVoxelLocalSearch.Minimize`: градиентная приоритизация соседей, знак допустимой области, критерий локального минимума | минимум выпуклого квадратичного поля с ограничением и без |

Тесты исполняются отдельно для Linux и Windows через `.github/workflows/functional-voxel-ci.yml`.

## Пример для будущего CAD

```csharp
using DCad.FunctionalVoxel;
using DCad.Core;

var sphere = FunctionalField.Sphere(0, 0, 0, 20);
var hole = FunctionalField.CylinderZ(0, 0, 5, -25, 25);
var part = sphere.Difference(hole);

var grid = new FunctionalGrid(
    new[] { -25.0, -25.0, -25.0 },
    new[] { 1.0, 1.0, 1.0 },
    new[] { 50, 50, 50 });

var model = FunctionalVoxelModel.Sample(part, grid);
var images = model.EncodeRgb24();          // 5 M-образов
var restored = images.ToModel();            // декодирование слоёв
var mesh = FunctionalIsoSurface.Extract(restored);
if (mesh is not null)
{
    var diagnostics = MeshValidator.Validate(mesh);
    Console.WriteLine($"Triangles = {mesh.Triangles.Count}, volume = {mesh.SignedVolume()}");
}
```

## Принципиальные ограничения и следующие этапы

1. **Не доказана побитовая совместимость с авторским ПО.** Формулы локальной гиперплоскости и R0 математически сопоставимы с опубликованным подходом, но выбор нормализации, сетки, интерполяции и диапазонов кодирования является инженерной реализацией. Точные настройки RGB24 из всех первоисточников ещё не верифицированы. Указание «точность до 5-го знака» не следует автоматически из 24-битной упаковки без выбранного диапазона.
2. **Сингулярности.** В точке, где оба операнда R0 равны нулю, нормаль может быть неопределена. Программа явно сообщает ошибку, а не фабрикует производную. Поверхность, проходящая строго через центр ячейки, также требует иной политики обработки, пока извлечение сетки сигнализирует ошибку.
3. **Точность производных.** Хранение локальной гиперплоскости даёт точную первую производную относительно исходной аналитической функции в центре выборки. Вторые производные по М-образам вычисляются конечными разностями; третий аналитический порядок пока не реализован.
4. **Интегрирование** численное: граница Коши задана в первом центре линии, не на внешней границе. Нет универсального решателя ОДУ/ДУЧП по методике работ 2022–2024.
5. **Проекционный принцип 2025** реализован только на уровне подъёма измерений и аффинного преобразования аргументов. Автоматического восстановления 3D по комплекту чертежей, законов вращения для сложных профилей, комбинаторного анализа проекций нет.
6. **Другие направления научной школы:** реализован лишь базовый локальный градиентно-ориентированный перебор по соседним вокселям, **не точное воспроизведение** алгоритма из статьи 2017 года. Роботы/траектории, скелетизация, напряжения, интегральные характеристики поверхности, произвольные нелинейные задачи, адаптивная разреженная решётка не заявляются реализованными.
7. **Извлечение поверхности** — дискретная полигональная аппроксимация; не сертифицировано на вырожденных/самопересекающихся объектах. Это не заменяет геометрическое ФВ-представление.
8. Нет интерактивного интерфейса намеренно: до научной и численной валидации ядра UI не разрабатывается. Установлен только общий проект в solution; parser языка `.dcad` ещё не использует ФВМ.
