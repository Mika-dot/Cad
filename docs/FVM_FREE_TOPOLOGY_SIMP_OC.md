# Свободная топологическая оптимизация в ФВМ + 3D FEM (исследовательский код)

Дата: 13.10.2026. Ветка: feature/fvm-generative-mechanics.
Файлы: experiments/FvmGenerativeDemo/FreeTopologyDesign.cs, HexFem.cs,
free_topology_3_bodies.json, .github/workflows/fvm-generative-demo-ci.yml.

## 1. Что изменилось

До этого существовали **только параметрические радиусы** заранее найденных
основных маршрутов и 3D-раскосов. Даже режим autoTruss не был свободной
топологической оптимизацией.

В новом режиме --free-topology каждая неконсервативная ячейка пространства
проектирования имеет собственную числовую переменную rho_i ∈ [0.01,0.99].
Переменные задают непрерывное поле F(x,y,z), его производные, согласованные
пять M-образов и жёсткость элементов FEM. Поэтому перемычки, пустоты и
каналы **могут возникать в разрешённой области**, не имея соответствующих
заранее нарисованных труб или маршрутов.

Вход — **только базовые обязательные тела**, роли fixed/load/anchor,
физические нагрузки, материал, запрещённые геометрии. Для этих тел не
нужно задавать соединительные линии, сетку ферм или индивидуальные
механические узлы. Необходимость назначать реальные физические
закрепления при этом остаётся: геометрия сама по себе не определяет, к
чему изделие прикручено.

## 2. Непрерывная функция и пять M

На регулярной сетке центров ФВМ хранятся управляющие rho_i.
Сначала они сглаживаются нормированным 3D фильтром 3×3×3:

    rho_smooth(i) = sum_j w_ij rho(j), sum_j w_ij = 1

В любой точке p используется трёхлинейная интерполяция этих значений
по центрам ячеек:

    rho_smooth(p) = sum_{i из 8 соседних центров} N_i(p) rho_smooth(i)

Для согласования с существующей сглаженной моделью Hex8 задаётся
поле со знаком материал/пустота:

    F_design(p) = 2 epsilon (rho_smooth(p)-0.5)
    H_epsilon(F) = clamp(0.5 + F/(2 epsilon), 0, 1)

Следовательно, внутри однородной проектной области
H_epsilon(F_design) = rho_smooth(p).

Все базовые тела оставляются как обязательная геометрия:

    F_keep(p) = max(F_body_1(p), ..., F_body_n(p))

Положительные значения **внутри** защищённых тел поднимаются как
минимум до epsilon, чтобы не превращать их в полуматериал.
Запрещённые объёмы с margin и внешняя граница домена отсекаются
неявными операциями:

    F_total = min(max(F_design,F_keep),
                  F_bounding_margin,
                  -F_obstacle_1-clearance_1-safety,
                  ...)

Это пока Lipschitz-совместимая CSG-эвристика, но не регуляризованная
R-функция с гарантированной гладкостью: max/min имеют
недифференцируемые границы переключения.

На центрах FunctionalGrid из F_total и трёх пространственных
центральных производных формируются локальные гиперплоскости:

    a_x*x + a_y*y + a_z*z + a_F*F + a_0 = 0

Именно пять коэффициентов M0..M4, нормированных совместно согласно
основному ядру функционально-воксельного моделирования. FEM не
вычисляет из этих каналов отдельную плотность-фейк; он
восстанавливает F_M(x) по всем пяти каналам и применяет
материальный оператор H_epsilon(F_M).

## 3. 3D FEM и SIMP

Сборка на фоне 3D Hex8:

    K_e = sum_{g=1..8} w_g*B_g^T*D(E_g,nu)*B_g
    E_g = E0 [ e_min + (1-e_min) H_epsilon(F_M,g)^p ]

Программа имеет параметр simpPower=3 в новом режиме.
Старые режимы сохраняют simpPower=1 (потому что смена физики
без явного переключателя была бы регрессией).
Плотность для объёма/массы остаётся H_epsilon, а не H^p:

    V = sum_g w_g H_epsilon(F_M,g)
    m = rho_mass * V

Для каждого независимого набора внешних сил решается:

    K(F_M) u_k = f_k
    C_k = f_k^T u_k
    sigma_VM,k ; u_max,k ; R_k

Функция цели — минимизация средней податливости (compliance)
при уменьшающемся бюджете материала. Прочность/максимальные
перемещения и другие включённые в исходном JSON ограничения
проверяются как барьеры на каждом принимаемом шаге.

## 4. Почему градиент настоящий FEM/FVM, а не «процент удалить»

По симметричному FEM и теореме о сопряжённых производных:

    dC/dF_M(g) = -u^T [dK/dF_M(g)]u
    dV/dF_M(g) = w_g/(2 epsilon) [в гладкой полосе]

Учтена производная SIMP:

    dE/dF = E0(1-e_min) p H^(p-1) / (2 epsilon)

Для каждой точки Гаусса чувствительность возвращается в свободные
параметры через точный транспонированный путь (при фиксированном
выборе ветки CSG max/min):

    FEM Gauss -> multilinear blend of local M planes
              -> F and spatial-gradient finite difference stencils
              -> spatial trilinear control interpolation
              -> transpose normalized 3×3×3 filter
              -> design rho_i

Нормировка локальных M коэффициентов не меняет оцениваемую
касательную функцию, поэтому по значению и градиентам эта цепь
локально линейна. На местах переключения CSG направление
производной кусочно определяется активной веткой, общей
дифференцируемости здесь нет.

Существует отдельный флаг --gradient-check, вычисляющий
центральную конечную разность **полного FEM-комплаенса и объёма**,
с решением механики в двух немного отличающихся 5M-полях.
Это не сравнение двух формул градиента между собой.

## 5. Оптимизация

Управление: Optimality Criteria с ограничением изменения
на итерации и бисекцией множителя Лагранжа:

    rho_i(new) = clamp(rho_i * sqrt((-dC/drho_i)/(lambda*dV/drho_i)),
                       rho_i - 0.20, rho_i + 0.20, 0.01, 0.99)

Численно некоторые градиенты равны 0: деления защищены, шаг
принимается только по фактическому уменьшению V и
проверке прочности, перемещения, связности, нескольких
loadcases. При неудаче используется backtracking.

**Топологическое зарождение:** отдельный модуль выбирает
малоэнергетические свободные области и пробует сделать
локальный участок 3×3×3 практически пустым, независимо
от существующих маршрутов. Проект сохраняется только если
новая топология проходит статический FEM, проверки
мультифизических ограничений и независимую direct-F проверку.

Это не математически глобальный level-set/topological derivative:
зарождение реализовано дискретным эвристическим оператором,
а не теоремой оптимальности.

## 6. Прочность реально экспортируемой детали

Непрерывное SIMP-поле не совпадает с бинарной STL. Поэтому
для каждого принимаемого кандидата создаётся отдельный
**бинарный FEM по знаку F_M**, т.е. solid/void с ersatz
stiffness пустоты, без промежуточного SIMP-серого материала:

    solid(x) iff F_M(x) >= 0

Это механически отличается от основного оптимизационного расчёта.
Принимается только конструкция, которая соответствует заданным
статическим пределам и в этой бинарной постановке. В финальном
summary.json обязательно представлены binaryVolumeMm3,
binaryMaximumVonMisesMpa, binaryMaximumDisplacementMm
и binaryComplianceNmm.

Это значительный шаг к воспроизводимости, но **НЕ**
независимая промышленная конечно-элементная сетка самого
STL: binary FEM всё ещё использует ту же фоновую Hex8-сетку.
Особенно недостоверны пиковые напряжения на острых границах.

## 7. Запуск

    git switch feature/fvm-generative-mechanics
    dotnet build experiments/FvmGenerativeDemo/FvmGenerativeDemo.csproj -c Release --warnaserror
    dotnet run --project experiments/FvmGenerativeDemo -c Release -- --free-topology experiments/FvmGenerativeDemo/free_topology_3_bodies.json --iterations 3 --gradient-check --self-test --out output/free

    python experiments/FvmGenerativeDemo/validate_stl.py output/free/initial.stl output/free/optimized.stl

Выход: initial.stl, optimized.stl, metrics.csv, density.csv, summary.json.

**free_topology_3_bodies.json** не содержит никаких вручную заданных
балок или ферм: только фиксируемая сфера, нагружаемый брусок,
обязательный эллипсоид, запрещённый цилиндр, общие физические
параметры и границы проектной области.

## 8. Что нужно отличать от промышленного результата

Сходимость на разной пространственной сетке h_FVM/h_FEM,
проверка динамики и термоупругости на фактически бинарном теле,
поверхностные вместо объёмных нагрузок, точные CAD-интерфейсы,
более строгая минимальная толщина,
регуляризация зависимости результата от сетки,
реальный уровень шероховатости / FDM анизотропия,
nonlinear contact, buckling, многомодовая FRF, полноценная
fatigue и экспериментальная механическая проверка.
Промышленной сертификации нет.

**Код не должен выдавать «оптимальная и выдерживает всё»
лишь на основании успешного итеративного PCG или воксельного STL.**

Тесты CI и фактические результаты с номером run хранятся в
experiments/FvmGenerativeDemo/TASK_JOURNAL.md.
