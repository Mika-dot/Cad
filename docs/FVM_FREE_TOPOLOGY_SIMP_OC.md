# Свободная топологическая оптимизация в ФВМ + 3D FEM (исследовательский код)

Дата: 13.10.2026. Ветка: feature/fvm-generative-mechanics.
Файлы: experiments/FvmGenerativeDemo/FreeTopologyDesign.cs, HexFem.cs,
free_topology_3_bodies.json, .github/workflows/fvm-generative-demo-ci.yml.

## 1. Что изменилось

До этого существовали **только параметрические радиусы** заранее найденных
основных маршрутов и 3D-раскосов. Даже режим autoTruss не был свободной
топологической оптимизацией.

В новом режиме --free-topology каждая неконсервативная ячейка пространства
проектирования имеет собственную числовую переменную rho_i ∈ [0.01,0.99].
Переменные задают непрерывное поле F(x,y,z), его производные, согласованные
пять M-образов и жёсткость элементов FEM. Поэтому перемычки, пустоты и
каналы **могут возникать в разрешённой области**, не имея соответствующих
заранее нарисованных труб или маршрутов.

Вход — **только базовые обязательные тела**, роли fixed/load/anchor,
физические нагрузки, материал, запрещённые геометрии. Для этих тел не
нужно задавать соединительные линии, сетку ферм или индивидуальные
механические узлы. Необходимость назначать реальные физические
закрепления при этом остаётся: геометрия сама по себе не определяет, к
чему изделие прикручено.

## 2. Непрерывная функция и пять M

На регулярной сетке центров ФВМ хранятся управляющие rho_i.
Сначала они сглаживаются нормированным 3D фильтром 3×3×3:

    rho_smooth(i) = sum_j w_ij rho(j), sum_j w_ij = 1

В любой точке p используется трёхлинейная интерполяция этих значений
по центрам ячеек:

    rho_smooth(p) = sum_{i из 8 соседних центров} N_i(p) rho_smooth(i)

Для согласования с существующей сглаженной моделью Hex8 задаётся
поле со знаком материал/пустота:

    F_design(p) = 2 epsilon (rho_smooth(p)-0.5)
    H_epsilon(F) = clamp(0.5 + F/(2 epsilon), 0, 1)

Следовательно, внутри однородной проектной области
H_epsilon(F_design) = rho_smooth(p).

Все базовые тела оставляются как обязательная геометрия:

    F_keep(p) = max(F_body_1(p), ..., F_body_n(p))

Положительные значения **внутри** защищённых тел поднимаются как
минимум до epsilon, чтобы не превращать их в полуматериал.
Запрещённые объёмы с margin и внешняя граница домена отсекаются
неявными операциями:

    F_total = min(max(F_design,F_keep),
                  F_bounding_margin,
                  -F_obstacle_1-clearance_1-safety,
                  ...)

Это пока Lipschitz-совместимая CSG-эвристика, но не регуляризованная
R-функция с гарантированной гладкостью: max/min имеют
недифференцируемые границы переключения.

На центрах FunctionalGrid из F_total и трёх пространственных
центральных производных формируются локальные гиперплоскости:

    a_x*x + a_y*y + a_z*z + a_F*F + a_0 = 0

Именно пять коэффициентов M0..M4, нормированных совместно согласно
основному ядру функционально-воксельного моделирования. FEM не
вычисляет из этих каналов отдельную плотность-фейк; он
восстанавливает F_M(x) по всем пяти каналам и применяет
материальный оператор H_epsilon(F_M).

## 3. 3D FEM и SIMP

Сборка на фоне 3D Hex8:

    K_e = sum_{g=1..8} w_g*B_g^T*D(E_g,nu)*B_g
    E_g = E0 [ e_min + (1-e_min) H_epsilon(F_M,g)^p ]

Программа имеет параметр simpPower=3 в новом режиме.
Старые режимы сохраняют simpPower=1 (потому что смена физики
без явного переключателя была бы регрессией).
Плотность для объёма/массы остаётся H_epsilon, а не H^p:

    V = sum_g w_g H_epsilon(F_M,g)
    m = rho_mass * V

Для каждого независимого набора внешних сил решается:

    K(F_M) u_k = f_k
    C_k = f_k^T u_k
    sigma_VM,k ; u_max,k ; R_k

Функция цели — минимизация средней податливости (compliance)
при уменьшающемся бюджете материала. Прочность/максимальные
перемещения и другие включённые в исходном JSON ограничения
проверяются как барьеры на каждом принимаемом шаге.

## 4. Почему градиент настоящий FEM/FVM, а не «процент удалить»

По симметричному FEM и теореме о сопряжённых производных:

    dC/dF_M(g) = -u^T [dK/dF_M(g)]u
    dV/dF_M(g) = w_g/(2 epsilon) [в гладкой полосе]

Учтена производная SIMP:

    dE/dF = E0(1-e_min) p H^(p-1) / (2 epsilon)

Для каждой точки Гаусса чувствительность возвращается в свободные
параметры через точный транспонированный путь (при фиксированном
выборе ветки CSG max/min):

    FEM Gauss -> multilinear blend of local M planes
              -> F and spatial-gradient finite difference stencils
              -> spatial trilinear control interpolation
              -> transpose normalized 3×3×3 filter
              -> design rho_i

Нормировка локальных M коэффициентов не меняет оцениваемую
касательную функцию, поэтому по значению и градиентам эта цепь
локально линейна. На местах переключения CSG направление
производной кусочно определяется активной веткой, общей
дифференцируемости здесь нет.

Существует отдельный флаг --gradient-check, вычисляющий
центральную конечную разность **полного FEM-комплаенса и объёма**,
с решением механики в двух немного отличающихся 5M-полях.
Это не сравнение двух формул градиента между собой.

## 5. Оптимизация

Управление: Optimality Criteria с ограничением изменения
на итерации и бисекцией множителя Лагранжа:

    rho_i(new) = clamp(rho_i * sqrt((-dC/drho_i)/(lambda*dV/drho_i)),
                       rho_i - 0.20, rho_i + 0.20, 0.01, 0.99)

Численно некоторые градиенты равны 0: деления защищены, шаг
принимается только по фактическому уменьшению V и
проверке прочности, перемещения, связности, нескольких
loadcases. При неудаче используется backtracking.

**Топологическое зарождение:** отдельный модуль выбирает
малоэнергетические свободные области и пробует сделать
локальный участок 3×3×3 практически пустым, независимо
от существующих маршрутов. Проект сохраняется только если
новая топология проходит статический FEM, проверки
мультифизических ограничений и независимую direct-F проверку.

Это не математически глобальный level-set/topological derivative:
зарождение реализовано дискретным эвристическим оператором,
а не теоремой оптимальности.

## 6. Прочность реально экспортируемой детали

Непрерывное SIMP-поле не совпадает с бинарной STL. Поэтому
для каждого принимаемого кандидата создаётся отдельный
**бинарный FEM по знаку F_M**, т.е. solid/void с ersatz
stiffness пустоты, без промежуточного SIMP-серого материала:

    solid(x) iff F_M(x) >= 0

Это механически отличается от основного оптимизационного расчёта.
Принимается только конструкция, которая соответствует заданным
статическим пределам и в этой бинарной постановке. В финальном
summary.json обязательно представлены binaryVolumeMm3,
binaryMaximumVonMisesMpa, binaryMaximumDisplacementMm
и binaryComplianceNmm.

Это значительный шаг к воспроизводимости, но **НЕ**
независимая промышленная конечно-элементная сетка самого
STL: binary FEM всё ещё использует ту же фоновую Hex8-сетку.
Особенно недостоверны пиковые напряжения на острых границах.

## 9. Дополнительная математическая проверка и проекция Хевисайда (13.10.2026)

Реализован опциональный `"projectionBeta":3` на уровне JSON.
При `projectionBeta=0` (значение по умолчанию) работает строго
тождественная проекция — это сохраняет **все** ранее проверенные
численные постановки и позволяет воспроизводить прежние эксперименты.

При beta>0 после нормированного фильтра и пространственной
интерполяции `rho_filtered(p)` применяется гладкая проекция:

```text
eta = 0.5
P_beta(rho) = [tanh(beta*eta)+tanh(beta*(rho-eta))] /
              [tanh(beta*eta)+tanh(beta*(1-eta))]

P'_beta(rho) = beta [1-tanh²(beta*(rho-eta))] /
               [tanh(beta*eta)+tanh(beta*(1-eta))]

F_design(p) = 2 epsilon [P_beta(rho_filtered(p))-0.5].
```

Производная `P'_beta` входит **внутрь действительной
транспонированной цепи**: Gauss/Hex8 →
пять M-гиперплоскостей → численный пространственный градиент F →
проекция P → пространственные веса → транспонированный density-filter.
Это не случайное бинарное порогование уже вычисленного STL.
Для beta=3 проверены конечными разностями **три пространственно
разнесённых** компоненты градиента податливости и объёма.

**Воспроизводимый независимый CI:**
[Projected Heaviside #38396472796](https://github.com/Mika-dot/Cad/actions/runs/38396472796), PASS.

| Эксперимент | Количество переменных | Изменения | Новые отверстия | Начальный FEM объём, мм³ | Конечный FEM объём, мм³ | Относительное изменение |
|---|---:|---:|---:|---:|---:|---:|
| beta=3, 3 обязательных тела | 388 | 4 | 1 | 50599.47 | 37712.15 | −25.469% |

STL сокращён на **28.612%**, замкнут, ориентирован и односвязен как
отдельная поверхность. Не следует безоговорочно утверждать, что
beta=3 «лучше» beta=0: они имеют **разный начальный объём и разные
дискретные поля**, сравнение требует одинаковой методики оценки,
сходимости и физических нагрузок.

## 11. Мультифизика и ограничение доверия к сетке

В отдельной сцене `free_topology_multiphysics.json` реализованы
одновременно 2 статических случая, первая мода, гармонический
одномодовый отклик, линейный Newmark на полусинус внешней силы,
стационарная 3D теплопроводность, тепловая деформация и упрощённая
fatigue Basquin. Кандидат проходит все активные условия отдельно
на 5M, direct-F и бинарном экспортируемом знаке 5M.

Первоначальный эксперимент при температурной разности 80 K правильно
отказался проходить из-за превышения напряжений и перемещений.
В ходе аудита устранена реальная ошибка SIMP-термоупругости:
`K_e` использовала `rho^p`, а эквивалентная температурная нагрузка —
`rho`, что некорректно для `p≠1`.
Теперь **оба** учитывают `E_min+(1-E_min)*rho^p`.
Проверено независимым однородным тестом:
`rho=0.5`, `p=1` и `p=3` дают
`u_th=0.0121180893651 мм` и `VM=3.90670941 МПа`
в пределах округления.

[Multiphysics CI #38386829988](https://github.com/Mika-dot/Cad/actions/runs/38386829988):
при разности 20 K без изменения требований прочности итог
**−5.972%** FEM-объёма, **−7.508%** STL-объёма.

**Особо важно**: при увеличении Hex8 сетки с `10×7×6`
до `15×11×9` конечный бинарный расчёт показал изменение
максимального напряжения **на 35.03%**, перемещения на **10.78%**,
объёма на **−2.00%**. Следовательно текущая грубая модель
**не прошла критерий сеточной сходимости**.
Численные результаты демонстрируют функционирование реализации,
но не гарантируют прочность для производства или сертификации.
В качестве P0 дальнейшей работы нужны автоматическое
`h_FEM/h_FVM/epsilon`-исследование, физически корректные
поверхностные силы/давления и независимый tetra/surface-fit FEM.

Полный журнал и команды запуска:
[experiments/FvmGenerativeDemo/TASK_JOURNAL.md](../experiments/FvmGenerativeDemo/TASK_JOURNAL.md).


## 12. Трёхуровневая проверка сеточной сходимости — реальная ошибка FEM

Прежнее измерение на двух сетках явно показало недостаток точности.
Поэтому добавлен `--refinement-report` c **тремя независимыми
Hex8 сетками** для одной и той же финальной *бинарной*
геометрии `sign(F_M)`.

[CI #38397025363](https://github.com/Mika-dot/Cad/actions/runs/38397025363):
комплексный 3-body multiphysics тест; согласованные физические
нагрузки, ограничения и материал:

| Переход | Изменение бинарного объёма | Изменение максимального VM | Изменение максимального перемещения |
|---|---:|---:|---:|
| 10×7×6 → 15×11×9 | −2.00% | +35.03% | +10.78% |
| 15×11×9 → 20×14×12 | +1.22% | +13.69% | −10.09% |

При обновлённом консервативном экране необходимы
**оба последовательных уточнения**: изменение VM/перемещения
ниже 10% и объёма ниже 5% на КАЖДОМ переходе.
Даже если последнее изменение стало небольшим, большое первое
не разрешает объявить сходимость. Для данных таблицы результат
**MESH CONVERGENCE SCREEN: NOT CONVERGED**.

В `summary.json` теперь явно присутствуют
`meshConvergenceScreenPassed: false` и
`verifiedManufacturingStrength: false`.
Математически честно говорить, что расчёт удалось **выполнить и
проверить на известных ограничениях**, но **не** что получена
сертифицированная точность конструкции.

Для инженерного отказа при недоказанной сходимости добавить
`--require-mesh-convergence` вместе с `--refinement-report`.
Если три сетки не сходятся, программа завершится ошибкой, откажется
объявлять изделие проверенным. Если другая сцена проходит этот
ориентировочный экран, она всё равно требует ещё более строгой
физической верификации: три сетки не дают апостериорной
гарантированной верхней ошибки.

**Причина вероятной медленной сходимости:** фоновый Hex8 с
дискретным материальным индикатором на точках Гаусса
вместо conforming mesh,
жёсткие объёмные узлы без механических контактов, грубая
внутренняя геометрия 5M и концентрации напряжений.
Для снижения VM-ошибки нужно улучшать интегрирование
границы/тетраэдральную сетку, а не только ещё сильнее
уменьшать допуск PCG.


## 12. Валидация входных инженерных условий до FEM (13.10.2026)

Предположение, что пользовательские `preserve` и `avoid` не пересекаются,
обязательно для корректного FVM-поля:

```text
для любого обязательного тела B_i и запретной области O_j:
B_i ∩ (O_j с заданным clearance + геометрический safety) = ∅.
```

В реальном 6-body эксперименте обнаружен конфликт: обязательный
цилиндр пересекался с запрещённым `lower-block` за пределами своей
внутренней точки `seed`. До введения объёмной проверки программа
могла не заметить противоречие и вырезать защищённую поверхность.
Это **некорректная инженерная постановка, а не возможность
оптимизировать несущую систему**.

Добавлена проверка обязательных тел по сетке контрольных пространственных
точек. Исправлены **все три** наследовавшие конфликт
сцены (`multi_scene_6_bodies.json`, `free_topology_6_bodies.json`,
`multi_scene_auto_truss.json`): препятствие `lower-block`
имеет центр `[38,-6,-6]`, полурасмеры `[6,5,6]` мм.
Требование обхода двух препятствий и защищённая цилиндрическая
деталь сохранены.

Добавлена быстрая явная проверка структуры JSON:
```powershell
dotnet run --project experiments/FvmGenerativeDemo -c Release -- --validate-scene experiments/FvmGenerativeDemo/multi_scene_6_bodies.json
```

При несовместимых исходных телах/запретных областях программа
завершается с диагностикой, **без FEM и без выдачи конструкции**.
Отрицательные регрессионные проверки специально реконструируют
старое пересечение и требуют отказа. CI:
[contract validation](https://github.com/Mika-dot/Cad/actions/workflows/fvm-scene-validation.yml).

## 13. Уточнение диагностики FEM — оба перехода, не последний

При анализе давления по реальной STL-сетке обнаружено, что
`10×7×6 → 15×11×9` давало **+57.33%** к максимальному
напряжению Мизеса, а `15×11×9 → 20×14×12` всего **+3.76%**.
Предыдущий алгоритм оценивал лишь второй переход и мог вернуть
`meshConvergenceScreenPassed=true`, хотя на первом переходе
сдвиг напряжения был очень значительным.

Исправлено в `FreeTopologyDesign.cs`:
```text
Для каждого из ДВУХ переходов (h0 -> h1, h1 -> h2):
    abs(Δsigma_VM)/sigma_VM(previous) < 10%
    abs(Δu)/u(previous) < 10%
    abs(ΔV)/V(previous) < 5%

Экран PASS только если соблюдены все шесть механических ограничений
и два ограничения на объём.
```

В `mesh_refinement.json` теперь сохраняются
`transitions[]` с каждой парой исходных/новых сеток,
все три относительные погрешности и
`maxAbsRefinement{Volume,Stress,Displacement}Percent`.
При невозможности получить три уровня из-за верхней границы
25 ячеек на ось экран не может объявить сходимость.

`--require-mesh-convergence` по-прежнему запрещает
экспорт `optimized.stl` при отрицательном результате.
Даже PASS трёх сеток не является математическим
доказательством апостериорной оценки ошибки для
сложной поверхностной STL/контактной геометрии.
