# Sphere Assembly — ФВМ с нуля, одной консолью

Отдельная учебная ветка **`assembly/sphere-from-zero`** репозитория `Mika-dot/Cad`. Создана от пустого дерева (не содержит проектов DCad, UI или исходников из других веток).

Это максимально простой пример **функционально-воксельного представления**: один `Program.cs`, один `SphereAssembly.csproj`, .NET 8, без сторонних зависимостей. Он предназначен для пошагового изучения математической идеи, а не для проектирования деталей.

## Запуск (Windows, PowerShell / Windows Terminal)

Нужен [Microsoft .NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0).

```powershell
git clone https://github.com/Mika-dot/Cad.git
cd Cad
git switch assembly/sphere-from-zero
dotnet run
```

Если репозиторий уже скачан:

```powershell
git fetch origin
git switch assembly/sphere-from-zero
dotnet run
```

В результате программа **цветом прямо в терминале** рисует каждую из 4 карт M для двумерного круга и 5 карт M на **каждом слое Z** для трёхмерной сферы. Цвет — это 24-битное RGB-число, соответствующее нормированному коэффициенту; не декоративная палитра. Под ними идут полные строки с координатами, F, значениями M и кодами #RRGGBB.

В папке `output/` появятся **4 + 5×N BMP-файлов**, по одному на М-образ и Z-слой (по умолчанию N=7, всего 39 файлов). Их можно открыть в обычном Windows Paint и увеличить без размытия; каждый пиксель соответствует одному центру ячейки.

В командах ниже `--` отделяет параметры `dotnet run` от параметров программы:

```powershell
dotnet run -- --size 7
dotnet run -- --size 11 --no-table
dotnet run -- --no-color
dotnet run -- --check
```

`--size` — нечётное число 3–21: сколько ячеек вдоль каждой оси. `--no-table` — только цветные картинки, без подробного списка всех вокселей. `--no-color` — вместо цветных прямоугольников печатает код RGB каждого пикселя. `--check` — детерминированная самопроверка формул, упаковки цветов и BMP, без основного вывода; маркер успешного результата: `SELF_CHECK_PASS`.

При перенаправлении вывода в файл или терминале без поддержки ANSI TrueColor выводятся HEX-коды. На Windows 10/11 приложение пробует включить режим VT-консоли самостоятельно.

## Что вычисляется

Одна функция для обеих демонстраций, радиус **3 мм**:

- круг: `F(x,y)=9-x²-y²`, функция двух аргументов;
- сфера: `F(x,y,z)=9-x²-y²-z²`, функция трёх аргументов.

Значение `F>0` внутри, `F=0` на границе, `F<0` снаружи. Значение F **не равно расстоянию**.

В каждом центре ячейки `p` вычисляются:

1. `F(p)`.
2. `grad F = (-2x,-2y)` для круга или `(-2x,-2y,-2z)` для сферы.
3. Локальная **линейная** модель `u ≈ F(p) + grad F(p)·(X-p)`.
4. Её однородное уравнение `a0*x + a1*y [+ a2*z] + a_u*u + a_const = 0`.
5. Нормировка всех коэффициентов одним множителем `L=sqrt(sum(a_i²))`: `M_i = a_i/L`.
6. Превращение каждого `M_i∈[-1,1]` в один RGB24-код: `RGB_i=round((M_i+1)×(2²⁴−1)/2)`.

Четыре M-образа появляются при **2D**, потому что это коэффициенты `(x,y,u,свободный)`. Для настоящей **3D-сферы требуется пять M-образов**, потому что они отвечают `(x,y,z,u,свободный)`. Отдельного четвёртого пространственного измерения нет: `u` — это значение функции.

Для вокселя **(2,1,1)** (R=3) получаем:

```text
F(2,1,1) = 3
градиент = (-4,-2,-2)
локальное уравнение: 4x + 2y + 2z + u - 15 = 0
нормирующая длина L = sqrt(250) = 15.8113883008

M0 =  4/L =  0.2529822128
M1 =  2/L =  0.1264911064
M2 =  2/L =  0.1264911064
M3 =  1/L =  0.0632455532
M4 =-15/L = -0.9486832981

восстановление: u = -(M0*x + M1*y + M2*z + M4)/M3 = 3
```

В конце программы эти же коэффициенты и цвета выводятся отдельно для ручной проверки.

## Как читать выведенные слои

Для круга печатаются 4 карты M0–M3 по XY. Для сферы цикл проходит Z от нижнего среза к верхнему, и **для каждого Z выводит пять соседних карт**. В BMP имя `sphere_Z+01_M2.bmp` означает слой `z=+1` и коэффициент при `z`.

Таблица каждого вокселя показывает `M0=0.123456 ... | M0=#9ABCDE ...`. Это связь между математическим коэффициентом и пикселем картинки. Если открыть BMP с большим масштабом, цвета должны соответствовать HEX-кодам.

## Границы научного соответствия

Учебный пример показывает **основной механизм формирования М-образов**, но не претендует на полную реализацию исследований Толока: здесь нет R-операций над вокселями, аналитических сложных тел, геометрических преобразований, интегральных алгоритмов и исходного авторского RGB-формата с `P=2²⁴` без адаптации границ. Здесь `P-1` обеспечивает законные коды от `000000` до `FFFFFF`. Это следует явно отличать от точной побитовой совместимости с оригинальным программным обеспечением.

С математикой можно сравнить:
- А. В. Толок, Н. Б. Толок. «Функционально-воксельный метод компьютерных вычислений», *Научная визуализация*, 2017: https://sv-journal.org/2017-2/01/
- А. В. Толок, Н. Б. Толок. «Проекционный принцип построения функционально-воксельных моделей», *Онтология проектирования*, 2025: https://journals.ssau.ru/ontology/article/view/29288

**Важно:** один воксель хранит не четыре/пять нарисованных картинок, а четыре/пять численных коэффициентов. Каждая картинка является **слоем одного типа коэффициента сразу для всех вокселей**. В 3D — набор XY-карт по каждому Z, как показано в программе.
