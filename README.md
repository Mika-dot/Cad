# Сфера: функционально-воксельный метод в одной консольной программе

Самая простая учебная реализация на C# (.NET 8). **Только два рабочих файла**: `Program.cs` и `SphereAssembly.csproj`. Без CAD, OpenGL, интерфейсов и сторонних библиотек.

## Запуск

```powershell
git clone https://github.com/Mika-dot/Cad.git
cd Cad
git switch assembly/sphere-from-zero
dotnet run
```

Если репозиторий уже скачан:

```powershell
git fetch origin
git switch assembly/sphere-from-zero
dotnet run
```

Лучше использовать **Windows Terminal** (поддерживает ANSI TrueColor). В консоли появятся все Z-слои сферы. В каждой строке показаны бок о бок **четыре картинки M0, M1, M2, M3**: каждый цветной квадратик — RGB24-код коэффициента для одного пикселя. Если терминал не умеет TrueColor, откройте сохранённые картинки в `output/`.

## Где что менять

В `Main` всего три настройки:

```csharp
Func<double, double, double, double> sphere =
    (x, y, z) => 9 - x * x - y * y - z * z;

double pixelStepMm = 1; // шаг пикселя в миллиметрах
double fromMm = -3;     // начало по каждой оси
double toMm = 3;        // конец по каждой оси
```

Можно написать **любую достаточно гладкую** функцию `(x,y,z) => ...`. Класс `FunctionPixels` сам оценивает производные, строит локальное уравнение и возвращает четыре RGB-цвета.

Для каждой пары `(x,y)` и фиксированного `z` получаем локальное уравнение:

```text
M0*x + M1*y + M2*F + M3 = 0
```

В классе всё записано по шагам, без скрытых библиотек:

1. Вычислить `F(x,y,z)`.
2. Рассчитать изменение F по X и Y по двум соседним пробам с каждой стороны (центральная разность).
3. Получить четыре коэффициента локальной плоскости.
4. Разделить их на общую длину (нормировать).
5. Каждое число от −1 до +1 перевести в код `#000000..#FFFFFF`.
6. Вернуть четыре цвета в `Main`.

`Main` просто выполняет циклы Z → Y → X и печатает четыре цветные карты. **По умолчанию семь срезов**, и для каждого сохраняются четыре файла BMP, то есть **28 картинок**. Их можно открыть в Paint с увеличением, потому что исходные изображения имеют размер только 7×7 пикселей.

## Почему четыре, если сфера трёхмерная?

В данном примере вычисляется **двумерная функция на каждом фиксированном Z-срезе**: `F_z(x,y)=9-x²-y²-z²`. Поэтому 4 М-образа на каждом срезе — корректно. Но эти 4 коэффициента **не дают производную по Z** и сами по себе не заменяют полноценные 5 М-образов для независимой трёхмерной функции. Это намеренное упрощение для изучения.

Производные здесь вычисляются **приближённо**, численно; для произвольной гладкой функции точность зависит от выбранного шага. Кодирование RGB24 использует максимальное целое `2²⁴−1` вместо `2²⁴` для представления обоих концов диапазона. Это учебный пример, не точная копия авторского исследовательского ПО.
